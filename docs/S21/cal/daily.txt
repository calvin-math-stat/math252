SSSP: Single Source Shortest Paths
	Dijkstra's Algorithm finds all shortest paths from one starting
		point

Algorithm and examples (use java demo)

	Data
		M[u,v] = edge length from u to v (infinity if no edge)
		S : set of vertices that have been "dealt with"
		D[x] = length of shortest discovered path from s to x
		s : a vertex (source)

	Initialization
		M <- input to algorithm (graph represented as a matrix)
		s <- input to algorithm
		D[x] = M[s,x]
		S = {s}

	Update (until S = V, or until specified vertex enters S)
		1. Find w in V-S with D[w] minimum
		2. put w into S
		3. for all x in V-S D[x] = min(D[x], D[w]+M[w,x])


	C-like Code:
		// source:
		// http://www.cs.rochester.edu/u/leblanc/csc173/graphs/sssp.html

		DijkstraSSSP (int N, rmatrix &C, vertex v, rvector &D)
		{
		   set S;
		   int i;
		   vertex k, w;
		   float cw;

		   Insert(S,v);
		   for (k = 0; k < N; k++) D[k] = C[v][k];
		   for (i = 1; i < N; i++) {
			   /* Find w in V-S st. D[w] is minimum */
			   cw = INFINITY;
			   for (k = 0; k < N; k++)
				  if (! Member(S,k) && D[k] < cw) {
					 cw = D[k];
					 w = k;
				  }
			   Insert(S, w);
			   /* Forall k not in S */
			   for (k = 0; k < N; k++)
				  if (! Member(S,k))
					 /* Shorter path from v to k using w? */
					 if (D[w] + C[w][k] < D[k])
						D[k] = D[w] + C[w][k];
		   }
		} /* DijkstraSSSP */

Analysis and improvements (n vertices, e edges)

	As above:
		O(n) to initialize
		n updates
			each update is O(n)
				check each vertex x to see if x is new w in S
				for each vertex x, update D[x]

	Room for improvement
		better finding of w
			keep elements of V-S in a priority queue
			O(log(n)) time for each  access of priority queue
		better update of D
			notice that changes only occur when there is an edge
				from w to x for some x in V-S
			if we have graph as adjaceny list rather than matrix,
				we can consider only the necessary x's
			over the course of the algorithm each edge considered
				only one time

		result:
			Initialize in O(n)
			Maintaining Priority Queue: O(n log n)
				each vertex can be updated at most once per iteration
			Determining w: O(n log n)
				one dequeue per iteration
			Updating D O(e log n)
				each edge visited at most once
				each visit causes at most one delete/insert to pqueue

			Assuming n <= e <= n^2, this yields O(e log n)
				worse if e = n^2
				better if e < n^2 / log n
				so works better on sparser graphs

Using Dykstra to do APSP
	matrix: O(n^3) just like Warshall
	adj list: O(ne log n) -- better if graph is sparse

Bijection Principle: if f:A -> B is 1-1 and onto, then |A| = |B|
        this is the meaning of counting
        how to tell if f: A -> B is a bijection:
        given f(a) we can tell what a is.
        given any b we can find a with f(a) = b.

Interpretation: must count everything (can't miss anything)
		must count each thing only once (no double counting)

Application: if two sets have same size, counting one determines the
		size of the other.

	2d) fill in blanks with numbers (0-9) (repititions allowed)

    Product Rule: |A cross B| = |A| * |B|

Def'n of 1-tape TM
	input alphabet: \Sigma
		doesn't include "blank"
	tape alphabet: \Gamma \superseteq \Sigma
		includes "blank"

	init state: q_0
	"program": \delta: \Gamma x Q -> \Gamma x Q x {L,R,S}  (partial function)

Format of the Turing Machine file

The format for the Turing machine files is the following. The first line
indicates that this is A Turing Machine file. There should be no blank lines:

Line 1: ATM.
Line 2: name of the machine. For assignments use name(s) and assignment number
Line 3: all characters in the input alphabet, separated by spaces
Line 4: all characters in the tape alphabet, separated by spaces
Line 5: the number of tapes (N). They are numbered 0,…, N-1
Line 6: the number of tracks on tape 0 (T0)
Line 7: the number of tracks on tape 1 (if N > 1) (T1)
…
Line N+5: the number of tracks on tape N-1 (TN-1)
Line N+6: 1 or 2, indicating tape 0 is 1-way or 2-way infinite tape
Line N+7: 1 or 2, indicating tape 1 is 1-way or 2-way infinite
…
Line 2N+5: 1 or 2, indicating tape N-1 is 1-way or 2-way infinite
Line 2N+6: the initial state of the Turing machine
Line 2N+7: all the final states separated by spaces
Line 2N+8: first of a list of transition (see below)
Line 2N+9: another transition
…
Line 2N+?: last of the list of transitions
Last line: end. You must type the word "end" but it can be upper or lower case

The format of a transition is:

<state> <content of tracks> <next-state> <next content of tracks> <head-move directions>

where

the <state> and <next-state> are the names of states (simple strings). When
the state has multiple fields such as [q0,a,b], there can be no spaces. This
compound state is handled in the simulator as a single string, without spaces.

the <content of tracks> and <next content of tracks> have the general form:
X1+X2+X3+…+XL, where L is the total number of tracks, i.e. L is the sum of T0,
T1, T2, …, TN-1 and the Xj are the symbols on the individual tracks above the
read/write head. Actually there is a read/write head for each tape but only
one is shown in the graphical simulator.

the <head-move directions> has the general form d1+d2+…+dN, where each dj is
R, L or S, indicating a right or left movement or staying stationary of the
tape head.

The Blank Symbol

As shown in the examples below, the blank tape symbol is denoted by "B" and
this symbol must not be used as part of the input alphabet. The blank symbol
is not shown on the tapes of the graphical simulator.

Example 1:

ATM
Hopcroft & Ullman’s TM for {0^n 1^n : n > 0} (file name tm1.txt)

end //required
